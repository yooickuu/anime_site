# yooickuu

Личный аниме-каталог с собственным плеером, списками и продолжением просмотра. Статическая часть подходит для GitHub Pages; аккаунты и личные данные обслуживает Supabase. Регистрация подтверждена владельцем; проверки синхронизации между аккаунтами ещё нужны.

## Запуск

Нужны Node.js 22+ и Python 3. В терминале в этой папке:

```sh
npm ci
npm run build
npm run dev
```

Открыть <http://127.0.0.1:4173/>. Остановка сервера — Ctrl+C. Через VS Code Go Live открывай `dist/index.html`, а не исходники. Не открывай HTML через `file://`: API и возврату из письма нужен HTTP-адрес.

## Аккаунты

Пошаговое подключение: [SETUP.md](SETUP.md) или [страница настройки на локальном сервере](http://127.0.0.1:4173/setup.html).

В `dist/config.js` хранятся только публичные Project URL и Publishable key. Секретные ключи, пароль базы, SMTP-пароль и токены видеоисточников туда добавлять нельзя. `npm run configure` проверяет публичный ключ перед сохранением. Таблицу, RLS и приватное хранилище аватарок создаёт `supabase/setup.sql`.

Регистрация по email, подтверждение адреса, вход и восстановление пароля реализованы через Supabase. Встроенная отправка писем ограничена: первый тест проводится с почтой владельца проекта. Для приглашения друзей потребуется собственный SMTP. Вход по телефону и Apple выключены до отдельной настройки провайдеров. Почта `@icloud.com` используется как обычный email и не требует Sign in with Apple.

## Каталог и видео

- **AniLiberty**: каталог, серии и HLS-потоки при доступности у провайдера. Аудит 14 октября 2026 года обнаружил 1 879 уникальных релизов. Это число релизов, а не гарантированно доступных видео.
- **AnimeVost**: второй видеоисточник, 3 598 полученных релизов. Публичный API, без токена. Прямые MP4-потоки воспроизводятся тем же плеером. 1 262 точных совпадения с AniLiberty объединены; в видеокаталоге 4 215 карточек после этого сопоставления (показатели на 14 октября 2026).
- **Kitsu**: дополнительные тайтлы, оригинальные обложки и метаданные. При проверке API сообщил о 22 500 записях. Kitsu не предоставляет видеопотоки.
- Тайтлы с общим ID объединяются по точному MyAnimeList ID. Для AnimeVost, где общего ID нет, дополнительно требуется совпадение полного названия, года и типа; неоднозначные варианты не склеиваются. Разные написания могут оставлять несопоставленные дубли. Разные сезоны сохраняются отдельно. Похожие названия сами по себе не считаются совпадением.
- Каталог загружается страницами с фильтрами; онгоинги отмечены. Режим всех каталогов включает карточки без подключённого видео; их можно сохранять в списки. Видеокаталог использует AniLiberty и AnimeVost; индекс второго источника обновляется пакетно ежедневной сборкой.
- Наличие релиза в каталоге не гарантирует доступность серий в конкретной стране. Ограничения провайдера по региону и правообладателям соблюдаются. Kodik пока не подключён.
- Собственный плеер воспроизводит HLS через Hls.js или нативную поддержку браузера. Кнопки, перемотка и настройки принадлежат yooickuu. На iPhone системный полноэкранный режим может показывать управление iOS.
- Загружать каждую серию вручную не нужно. Опционально можно выбрать локальные файлы; они не отправляются на сервер. Демо — отдельный трейлер Sintel, который не выдаётся за серию аниме.

Каталог и доступность зависят от внешних API. Нельзя обещать всё аниме мира, бесперебойную работу источников или права на распространение всех перечисленных произведений.

## Реализованные функции

- Светлая и тёмная темы; интерфейс RU / EN / JA; адаптивная раскладка, SVG-иконки и анимации с учётом `prefers-reduced-motion`. Перевод интерфейса не означает перевод всех описаний источников.
- Свои статусы просмотра, включая переименование и удаление стандартных. Именованные коллекции; один тайтл может быть в нескольких коллекциях.
- Никнейм, био и аватарка с перетаскиванием кадра, масштабом и двумя круглыми предпросмотрами; статистика просмотренных серий и средней оценки; сохранение списков, настроек и прогресса по сериям в аккаунте. Экспорт личных данных в JSON.
- Независимые переключатели пропуска опенинга/эндинга, перехода к следующей серии и её автозапуска. Пропуск использует таймкоды источника; ручной ввод секунд убран. Если источник не передал таймкоды (в том числе AnimeVost), автоматического распознавания заставок нет.
- Собственные выпадающие меню во всём интерфейсе. Компактный выбор серии и сезона; предыдущая/следующая кнопки скрыты на границах. Скорость, качество, звук, перемотка, полный экран, картинка в картинке и режим кино находятся в плеере. Автозапуск может быть ограничен браузером.
- Просмотр и сохранение требуют входа. Каталог доступен гостям. Это ограничение интерфейса сайта, а не защита общедоступных сторонних потоков от просмотра вне сайта.

## Проверки

```sh
npm test
npm run check
npm run build
npm run audit:catalog
npm run update:animevost
npm run audit:video
npm run audit:animevost
```

`audit:catalog` опрашивает каталог AniLiberty и сохраняет `checks/catalog-audit.json` и `dist/data/liberty-index.json`. Она проверяет уникальные ID и наличие полей обложек, а не воспроизведение каждой серии или доступность каждого изображения.

`audit:video` проверяет метаданные всех релизов/серий, один HLS-манифест каждого доступного релиза и небольшую выборку сегментов; `audit:animevost` — плейлисты всех релизов и HEAD первой видеоссылки. Это не просмотр всех серий целиком. Отчёты сохраняются в `checks/`, в публикацию не входят.

Автотесты проверяют списки, повторы операций, конфликты прогресса, переводы, сопоставление источников, фильтры, таймкоды, блокировки и публичную конфигурацию. Реальную регистрацию, доставку email, RLS с двумя аккаунтами и просмотр нужно проверять на подключённом проекте. Текущее состояние — в [PROGRESS.md](PROGRESS.md).

## GitHub Pages

В корень репозитория загрузи **содержимое этой папки `yoru`**, включая `.github`, `src`, `supabase`, `scripts`, `dist`, `package.json` и `package-lock.json`. `node_modules` загружать не нужно.

Workflow `.github/workflows/pages.yml` устанавливает зависимости, запускает тесты, обновляет индекс каталога, собирает приложение и публикует `dist`. В репозитории выбери Settings → Pages → Source → GitHub Actions. Workflow запускается при push в `main`, вручную и ежедневно по расписанию. Если API недоступен во время обновления индекса, сборка использует предыдущий индекс.

После публикации добавь точный адрес сайта в Supabase Authentication → URL Configuration и установи его как Site URL. GitHub Pages сам не создаёт пользователей и базу данных. Публикация ещё не выполнена.
