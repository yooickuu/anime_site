# Подключение yooickuu к Supabase

Для локального сайта открой <http://127.0.0.1:4173/setup.html>: там есть копирование SQL и ссылка на редактор своего проекта.

## 1. Публичное подключение

Создай проект Supabase на Free. В Connect или Settings → API Keys найди Project URL и Publishable key. Пароль базы и Secret key сайту не нужны. В терминале проекта выполни `npm run configure`, вставь URL и публичный ключ по очереди. Команда проверит связь и обновит `dist/config.js`. Не вставляй `sb_secret_…` или `service_role`.

## 2. База и аватарки

1. Скопируй `supabase/setup.sql` или нажми «Скопировать SQL» на странице настройки.
2. В своём проекте Supabase открой SQL Editor → New query.
3. Вставь SQL и нажми Run.
4. Ожидаемый ответ: `Success. No rows returned`.

Скрипт создаёт таблицу `yoru_state`, владельческие RLS-политики и приватное хранилище `avatars`. Не отключай RLS и не делай bucket публичным. SQL можно выполнить повторно: он пересоздаёт свои правила и не удаляет пользовательские записи. Приватный bucket `anime-media` предназначен для необязательных собственных медиа; загружать туда все аниме не требуется.

Запрос к таблице без входа получает `permission denied for table yoru_state` — это ожидаемо. Не выдавай права роли `anon` по подсказке API. После входа роль `authenticated` получает доступ только к строке своего пользователя.

## 3. Адреса возврата

Открой Authentication → URL Configuration. Пока сайт локальный, установи Site URL: `http://127.0.0.1:4173/`.

В Redirect URLs через Add URL добавь адреса, которыми пользуешься, каждый отдельно:

```text
http://127.0.0.1:4173/
http://127.0.0.1:4173/index.html
http://localhost:4173/
http://localhost:4173/index.html
http://127.0.0.1:5500/yoru/dist/index.html
http://localhost:5500/yoru/dist/index.html
```

Если Go Live открыт с другим путём, добавь точный адрес из адресной строки без `#…`. После публикации добавь адрес GitHub Pages, включая имя репозитория и завершающий `/`, и сделай его Site URL. Не присылай ссылки из писем подтверждения: они содержат одноразовые токены входа.

## 4. Первая регистрация

1. Обнови <http://127.0.0.1:4173/>.
2. Нажми Войти → Регистрация.
3. Для первого теста используй почту владельца проекта Supabase. Придумай отдельный пароль сайта от 8 символов.
4. Подтверди адрес из письма. При необходимости проверь спам.
5. После входа сохрани тайтл в список, обнови страницу и проверь, что он остался.
6. Создай свой статус и коллекцию, проверь изменение профиля и аватарки.
7. Открой доступную серию, посмотри немного, закрой и открой её снова — позиция должна восстановиться.

Встроенная почта Supabase предназначена для тестирования: письма только участникам проекта, лимит обычно 2 в час. `email_address_not_authorized` означает, что для этого получателя нужен собственный SMTP; `over_email_send_rate_limit` — лимит отправки. Повторные клики не обходят ограничение. Не отключай подтверждение email только ради обхода проблемы доставки.

## 5. Если после письма появляется «website can't be reached»

Сначала открой <http://127.0.0.1:4173/> на том же ноутбуке, где запущен сайт. Если он открывается, попробуй обычный вход: email мог подтвердиться до неудачного перехода. Повторная регистрация не нужна. Если сайт не открывается, запусти `npm run dev` в папке проекта.

Проверь начало адреса страницы с ошибкой (до `#` или `?`). Порт должен совпадать с работающим сервером. `localhost:3000` — стандартный адрес Supabase, который нужно заменить в Site URL; `5500` работает только при запущенном Go Live. Локальный адрес на телефоне указывает на сам телефон, поэтому до публикации ссылку нужно открывать на ноутбуке. Полный адрес из письма или адрес с токенами не отправляй в чат.

## 6. Доступ для друзей

Потребуется SMTP-сервис в Authentication → Email → SMTP Settings. Бесплатные условия зависят от провайдера; он может потребовать собственный домен. SMTP-пароль вводится только в Supabase, не в `dist/config.js`. Стоимость и условия нужно проверить перед подключением. До этого нельзя обещать регистрацию любому адресу.

Перед публикацией проверь из двух реальных аккаунтов, что список одного не доступен другому. Затем проверь сохранение после входа на втором устройстве. Это отдельная проверка RLS, не заменяемая успешным выполнением SQL.

## 7. Телефон и Apple

`phoneAuth` и `appleAuth` пока `false`. SMS требует провайдера, Sign in with Apple — отдельной настройки Apple. Бесплатность не гарантируется. Включать кнопки можно только после настройки и теста. Почта `@icloud.com` работает в email-форме при настроенной доставке писем.

Документация: [API keys](https://supabase.com/docs/guides/getting-started/api-keys), [Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls), [SMTP](https://supabase.com/docs/guides/auth/auth-smtp).
